- **Named deviation:** a transport failure (HTTP status, network, non-chat envelope) is `remote_infra_failure` — ineligible — and is never silently retried; upstream swallows exceptions inside the same five-attempt budget. A question ended by the confirmed wall envelope is `runtime_budget_exceeded` (ineligible, the aggregate harnesses' deadline label), not an infrastructure claim against the far end.
- **Transport:** one stdlib JSON POST per attempt to `<confirmed base_url>/chat/completions` over a direct `http.client` connection (no proxy resolution, no redirect following — a redirect would resend the credential elsewhere; any status but 200 is a transport failure) with the bearer credential from the provider profile's `api_key_env`, a body of exactly `model` and `messages`, no client-side retry. The credential is never logged, retained or echoed in an error.
- **Wall envelopes, both enforced:** the slice's `max_wall_clock_sec_per_instance` is one absolute deadline over a question's attempts and the plan's `max_wall_clock_sec` (per-instance × instances) one over the run. Each request is given only the allowance its question has left and that allowance bounds the **complete exchange** — a watchdog shuts the socket down at the deadline however much progress the far end is making, and its expiry is authoritative whether the cutoff surfaces as an exception or as a normal EOF — and a response that completes after the deadline is retained in the attempt record but never scored; none is started when nothing remains; a question the run has no room left for is a `runtime_budget_exceeded` row with zero requests and an empty attempts file. Only the dollar limit is an unenforced estimate.
- **Binding (CF1):** the plan's model binding snapshot fixes the vendor API name and the public endpoint at confirmation; the run sends the snapshot's `api_model` (not the logical id) and refuses, before any request or output reservation, an endpoint that changed since planning (`re-plan before launching`).
